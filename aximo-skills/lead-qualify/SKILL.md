# Квалификация входящего лида

## Шаг 1 — взять лид

Из заявки/карточки CRM берём то, что есть: имя контакта + корп.почта. Из почты — **домен**. По TLD и виду домена понимаем: `.ru` (или явно российский) → компания российская; любой другой → зарубежная.

## Шаг 2 — сайт

Заходим на сайт по домену: чем занимаются, размер, гео, чем могут быть интересны.

Для российской компании дополнительно ищем **ИНН**: подвал сайта, страницы «Контакты»/«Реквизиты»/«Юридическая информация», публичная оферта, политика конфиденциальности. Не нашли быстро — гуглим «<компания> ИНН» или смотрим ЕГРЮЛ. ИНН российской компании всегда публичен, тупика тут быть не должно.

## Шаг 3 — обогатить (дёшево, без интернет-поиска ЛПР)

- **Зарубежная** → через коннектор обогащения (Apollo/Clay/ZoomInfo — если подключён): фирмографика + пара релевантных контактов.
- **Российская** → маленьким скриптом по ИНН (DataNewton/СБИС/Контур.Фокус): выручка, численность, статус, владельцы/руководитель.

Полноценный поиск конкретных ЛПР в интернете — не здесь, это отдельный навык под холодный outbound.

## Шаг 4 — сверить с ICP

Читаем ICP из бизнес-CLAUDE.md (в практикуме — `aximo-CLAUDE.md`; в реальном проекте — `CLAUDE.md` проекта). Проходимся по критериям: размер, индустрия, гео, рутина/бюджет — по каждому ✓/✗.

## Шаг 5 — вердикт и запись

Вердикт: **КВАЛ** / **не КВАЛ** / **квал-с-оговоркой** + почему + рекомендованный заход.

С подтверждения записываем в CRM (`data.js`):
- обновляем карточку компании (домен, индустрия, гео, размер, сайт, ИНН — если РФ);
- добавляем заметку с вердиктом в сделку;
- **двигаем стадию**: КВАЛ/квал-с-оговоркой → `Qualified`, не КВАЛ → `Closed Lost` (с причиной) — лид не должен оставаться в «New».

Пересобираем доску после правок.

## Формат вывода

Вердикт (строкой) → Профиль компании → Сигналы по ICP (✓/✗) → Контакты (если есть) → Рекомендованный заход → Источники.

## Гейты безопасности

- Запись в CRM — только с подтверждения.
- Ключи сервисов — из `.env`, никогда не печатать.
- Ничего необратимого без явного «ок».
