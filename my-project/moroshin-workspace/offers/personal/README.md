# Персональные офферы

Один оффер на один продукт. Универсальный текст берётся из `offers/universal/offer-v2.md`, персональная часть (раздел 03: сегмент, пять компаний с сигналами, письмо) собирается под продукт по шаблону из `_template/`.

## Порядок сборки, около часа на продукт

1. **Продукт.** Сайт, что продаёт, кому, в чём обещание на главной, есть ли цена. Как устроены продажи сейчас: откуда пришли клиенты и пилоты (из разговора с фаундером или по косвенным признакам: кейсы на сайте, LinkedIn фаундера).
2. **Сегмент первой волны.** Где решает один человек и цикл короткий. Записать, почему он первый.
3. **Роли.** Чемпион (у кого боль) и кто платит. Одна строка.
4. **Пять компаний с сигналами.** Только открытые источники: вакансии в нужной функции, обещания на сайте («ответ на RFQ за 4 часа»), реестры поставщиков, участие в выставках и тендерах, новости о росте. У каждого сигнала ссылка. В репозитории курса для этого есть агент `/account-researcher` и урок L9.
5. **Первое письмо.** 60–90 слов, первая строка про сигнал, аргумент в деньгах покупателя, первый шаг короткий и конкретный. Навык `/cold-email` из курса даёт заготовку, финальную редакцию делать по `brand/text-style.md`.
6. **Два-три предложения для раздела 01** о том, как у них устроены продажи. Без оценок, только то, что видно.
7. Собрать `offer.md` из универсального текста и заполненного шаблона, проверить по чеклисту в `brand/text-style.md`, раздел 13.

## Где лежит

`offers/personal/<product>/` — `offer.md`, `appendix.md`, `NOTES.md` (контекст сделки, переписка, что ответили). Папки продуктов в git не попадают: репозиторий публичный, а в офферах данные о сделках. Исключение только `_template/` и этот файл.

Первый персональный оффер, ValveIQ, лежит в `offers/valveiq/` и собран до появления шаблона. Его приложение с десятью дистрибьюторами — образец раздела с компаниями.
